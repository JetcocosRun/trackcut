## 1. Цель продукта

Приложение **TrackCut** позволяет открыть видеофайл (MKV, MP4, MOV, WebM, AVI, TS и др.),
увидеть все дорожки (видео, аудио, субтитры, кнопки) и **удалить ненужные без перекодирования** —
то есть сделать remux: видеопоток и оставшиеся дорожки копируются бит-в-бит.

«Вырезать дорожки» = удалить потоки из контейнера, **не** обрезка по времени.
Обрезка по времени — вне скоупа (можно упомянуть в Roadmap, но не реализовывать).

## 2. Скоуп MVP

- Открытие файла через диалог, drag&drop и аргумент командной строки.
- Анализ контейнера: список дорожек с типом, кодеком, языком, названием, каналами,
  разрешением, битрейтом, default/forced-флагами, размером.
- Полные метаданные каждой дорожки (см. §8.1): язык + расшифровка, track name, все теги,
  задержка, размер и доля от файла — чтобы пользователь опознавал перевод, а не гадал.
- Прослушивание фрагмента (10–15 с) любой аудиодорожки до удаления.
- Чекбоксы «оставить/удалить» по каждой дорожке + быстрые пресеты:
  - «Только видео + лучшая аудио»;
  - «Видео + все аудио»;
  - «Видео + аудио + все субтитры»;
  - «Оставить только выбранный язык».
- Переключение default/forced у оставшихся дорожек.
- Опции: сохранять главы, теги, вложения (шрифты для ASS), track tags.
- Выбор выходного контейнера: MKV (по умолчанию), WebM, MP4/MOV, «как у входа».
- Пакетный режим: несколько файлов, одинаковый набор правил, отдельная папка вывода.
- Прогресс по каждому файлу, отмена операции, лог выполненных команд.
- Проверка результата после сборки и понятный отчёт.

## 3. Non-goals

- Перекодирование видео/аудио (кроме вынужденного `mov_text` для субтитров в MP4 — с предупреждением).
- Плеер, встроенный редактор, работа с кадрами.
- Работа с DRM, сетевые источники, стриминг.
- Кроссплатформенная синхронизация настроек.

## 6. Бэкенды и правила выбора

Два внешних инструмента, оба вызываются как процессы (не линкуем GPL-код):

| Задача | Инструмент |
|---|---|
| Метаданные MKV (точно, быстро) | `mkvmerge -J file` |
| Метаданные прочих контейнеров | `ffprobe -v error -show_streams -show_format -show_chapters -of json file` |
| Выход MKV/WebM | `mkvmerge` (лучше сохраняет теги/главы/вложения) |
| Выход MP4/MOV или вход не-MKV | `ffmpeg -map ... -c copy` |

Правило: **сначала mkvmerge, если вход и выход поддерживаются; иначе ffmpeg.**
Всегда проверять наличие инструмента; если выбранный недоступен — fallback с предупреждением в логе.

### 6.1. Probe

- MKV: `mkvmerge -J`. Парсить `files[].tracks[]`: `id`, `type` (`video/audio/subtitles/buttons`),
  `codec`, `properties.language`, `track_name`, `default_track`, `forced_track`,
  `num_channels`, `pixel_dimensions`, `tag_duration`, `default_duration`.
  Главы: `chapters`, вложения: `attachments`.
- Дополнительно для MKV: `ffprobe -of json`, чтобы получить **полный tag-map** каждой дорожки
  (`SOURCE`, `ENCODER`, `BPS`, `NUMBER_OF_FRAMES`, `DURATION`…) и точный битрейт/размер.
  `mkvmerge -J` отдаёт только базовые свойства. Записи объединять по порядку внутри типа;
  если тип/кодек не совпали — писать warning в лог и показывать данные mkvmerge как основные.
- Остальное: `ffprobe -of json`. Маппить `index`, `codec_type`, `codec_name`, `tags.language`,
  `tags.title`, `channels`, `width/height`, `bit_rate`, `disposition.default/forced`.
- Привести оба источника к единой модели `MediaInfo`. Индексы дорожек — **в терминах исходного
  инструмента probe**, и хранить отдельно `mux_id` для mkvmerge и `ff_index` для ffmpeg,
  чтобы не путать нумерацию.

### 6.2. Сборка через mkvmerge

Шаблон:
```
mkvmerge --gui-mode -o "<out.part.mkv>" \
  -a 1,3 -s 0,2 -d 0 -B \
  --no-chapters --no-global-tags --no-track-tags --no-attachments \
  --default-track 1:yes --forced-track 2:no \
  --track-order 0:0,0:1,0:2 \
  "<in.mkv>"
```
- `--gui-mode` даёт строки `#GUI#progress NN%` — парсить для прогресса.
- Exit code: `0` — успех, `1` — предупреждения (считать успехом, показать warning-лог), `≥2` — ошибка.
- Если дорожек типа нет — не передавать соответствующий `-a/-s/-d`, либо использовать `-A/-S/-D`.
- WebM: разрешены только VP8/VP9/AV1 + Vorbis/Opus + WebVTT; несовместимое — блокировать
  с объяснением, предлагать MKV.

### 6.3. Сборка через ffmpeg

```
ffmpeg -hide_banner -nostdin -y -i "<in>" \
  -map 0:0 -map 0:2 -map 0:5 \
  -c copy -map_metadata 0 -map_chapters 0 \
  -movflags +faststart -progress pipe:1 -nostats -loglevel error \
  "<out.part.mp4>"
```
- Селекторы — по **глобальным индексам** из ffprobe (`-map 0:<index>`), а не по `a:0` — надёжнее.
- MP4/MOV: PGS/VobSub/ASS несовместимы. Варианты в UI: удалить такие субтитры или
  конвертировать в `mov_text` (`-c:s mov_text` только для субтитров); по умолчанию — предупредить.
- `-map_chapters -1` если главы отключены.
- `-progress pipe:1` → `out_time_us`/`out_time_ms`, `progress=end`; длительность брать из probe.

### 6.4. Проверка результата

После успешного mux:
1. Файл существует, размер > 0.
2. Повторный probe: число дорожек совпадает с планом, типы/кодеки совпадают
   (для `mov_text` — ожидаемое исключение), длительность в пределах ±1 c от входа.
3. Только после этого — атомарное переименование `.part` → финальное имя.
4. При ошибке `.part` удаляется, исходник не трогается.

## 8. GUI: экраны и состояния

Одно окно, три зоны:
1. **Слева** — список файлов (пакет): имя, размер, статус, кнопка удалить из списка.
2. **Центр** — таблица дорожек выбранного файла: чекбокс, иконка типа, ID, кодек,
   язык, название, каналы/разрешение, битрейт, размер, тумблеры Default/Forced.
   Заголовки кликабельны для сортировки. Строки видео подсвечены, аудио и субтитры — разделены.
3. **Справа/снизу** — настройки вывода: контейнер, папка, шаблон имени (`{name}_clean.{ext}`),
   опции глав/тегов/вложений, кнопка «Собрать», общий прогресс, лог (раскрываемая панель).

Состояния: `Empty → Probing → Ready → Running(progress, cancel) → Done | Error`.
- Ошибки — inline, с кнопкой «Показать команду» и «Открыть лог».
- Не давать запустить mux, если не выбрано ни одной дорожки; предупреждать, если нет видео.
- Не перезаписывать входной файл: если выходной путь совпал с входом — автодобавить суффикс.
- Drag&drop: `egui::Context::input(|i| i.raw.dropped_files.clone())`.
- Русские строки — в одном модуле `i18n.rs` (структура со строками), чтобы потом добавить EN.
- Клавиши: `Ctrl+O` открыть, `Ctrl+Enter` собрать, `Esc` отмена.

### 8.1. Идентификация дорожек — ключевая функция

Пользователь должен понимать, **что за перевод** он удаляет, не открывая файл в плеере.

Колонки таблицы дорожек:
1. ☑ — оставить.
2. Тип: 🎬 видео / 🔊 аудио / 💬 субтитры / 🔘 кнопки.
3. ID (`mkv_id` / `ff_index`).
4. Кодек: `AAC LC`, `E-AC-3`, `DTS-HD MA`, `Opus`, `H.264`, `HEVC`, `PGS`, `ASS`…
5. Язык: код + расшифровка — `rus — Русский`, `ukr — Украинский`, `eng — Английский`.
   Нормализовать ISO 639-1/2 (`ru`, `rus`, `RUS`); `und`/пусто → «не указан».
6. **Название дорожки (`track_name`) целиком, без сокращений**, с tooltip.
   Типичные значения: «Дубляж», «LostFilm», «HDrezka», «Кубик в кубе», «Original»,
   «Комментарий режиссёра». Это главный ориентир при удалении.
7. Параметры: аудио — каналы (`2.0`, `5.1`) + layout, частота, битрейт;
   видео — разрешение, FPS, HDR; субтитры — формат (ASS/PGS/SRT), forced.
8. Default / Forced — тумблеры, меняющие флаги в выходном файле.
9. Размер и доля от файла (МБ, %): из контейнера, иначе оценка `bitrate × duration`.
10. Задержка (delay), если контейнер её отдаёт.
11. ▶ «Прослушать» — только у аудио.

Панель «Все теги» под таблицей для выбранной дорожки: показывать **весь** tag-map
(`SOURCE`, `ENCODER`, `BPS`, `DURATION`, `NUMBER_OF_FRAMES`, `HANDLER_NAME`, `LANGUAGE`, `TITLE`…),
с поиском по ключу/значению. Ничего не отбрасывать и не додумывать:
если метаданных нет — честно «не указано».

Правила:
- Пустой `track_name` → бейдж «Без названия» + подсказка «прослушайте фрагмент».
- Одинаковый язык у нескольких дорожек → «Русский #1», «Русский #2» рядом с именем.
- Фильтр/поиск по языку, названию и кодеку; группировка аудио по языку.
- Сортировка по любому столбцу; по умолчанию — тип, затем язык, затем имя.

Прослушивание (опознание перевода на слух):
- `ffmpeg -v error -ss <t> -t 15 -i "<in>" -map 0:<idx> -ac 2 -ar 48000 -f wav -y "<temp.wav>"`,
  где `t` — 10% длительности; воспроизведение через `rodio`/`cpal`.
- Кнопка ▶/■, кэш WAV на дорожку, во время mux прослушивание недоступно.
- Нет аудиоустройства / ошибка декодирования → сообщение в лог, приложение не падает.

## 9. Надёжность и безопасность

- Всегда писать в `<output>.part.<ext>` в **той же папке**, что и финал (атомарный rename).
- Никогда не удалять/перезаписывать исходник. При конфликте имён — `name (1).mkv`.
- Проверять свободное место (по размеру входа + 5%).
- Отмена = kill процесса + удаление `.part`.
- Windows: спавнить консольные инструменты с `CREATE_NO_WINDOW`
  (`std::os::windows::process::CommandExt`), иначе мигают окна.
- Вывод инструментов читать как байты и декодировать lossy (кодировки Windows).
- Пути с пробелами и юникодом — обязательный тест-кейс.
- Никаких `unwrap()`/`expect()` в рантайм-путях; `thiserror` для доменных ошибок,
  `anyhow` только на границе приложения.
